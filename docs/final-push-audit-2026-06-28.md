## What Works

The Rust-level pipeline is healthy. Passing tests cover:

- basic body text diffs;
- paragraph add/delete/reorder/split/merge;
- Unicode;
- multifile inputs;
- Git revision mode;
- basic formatting preservation;
- lists, enums, terms, tables, grids, and quotes;
- many page style changes;
- basic math changes;
- repeated function expansion ordering.

The current architecture is coherent: evaluate Typst, build annotated realized
trees, diff to path-addressed edits, apply edits to the new realized content,
and render.

## Definitely Wrong Corpus Cases To Automate First

These are good candidates for immediate non-visual regression tests because the
current generated output contradicts the source change or the modification log.

1. `45-package-showybox`

   Symptom: `modifications.txt` reports 0 modifications even though the source
   text inside showybox cards changed. This is open GitHub issue #10.

   Suggested assertion: diffing the case must produce at least one modification
   mentioning the changed body text, while preserving the box/card structure.

2. `103-repeated-macro-containers-with-one-edit`

   Symptom: `modifications.txt` reports 0 modifications even though the `Beta`
   card changes from waiting for data to waiting for approval.

   Suggested assertion: exactly the changed repeated macro expansion is owned
   and annotated; the unchanged `Alpha` and `Gamma` cards remain untouched.

3. `54-align-changed` as the representative wrapper case

   Symptom: the generated diff duplicates the aligned body: one plain new copy
   and one annotated copy. Similar failures appear in `55-pad-changed`,
   `57-columns-changed`, `58-stack-changed`, and `60-62` shape wrappers.

   Suggested assertion: wrapper body edits should produce one localized edit on
   the wrapper body and must not leave an extra plain new wrapper body behind.

4. `71-figure-caption-added`

   Symptom: adding only a caption duplicates the figure body in the generated
   output. The modification log is also garbled:
   `: Distribution of measurementsFigure`.

   Suggested assertion: the existing figure body remains present exactly once,
   and only the caption slot is inserted/styled. Extend the same fix to
   `72-figure-caption-deleted`, `73-figure-body-changed-caption-added`, and
   `89-show-figure-caption-template-changed`.

5. `50-footnote-changed`

   Symptom: the actual output drops the body text before the footnote marker and
   leaves the marker isolated. The footer diff itself is localized, but the
   marker site is not preserved correctly.

   Suggested assertion: the body text before and after the footnote marker must
   remain in order, and only the footnote body change should be annotated.

6. `90-opaque-graphic-replaced` / `91-raw-svg-graphic-replaced`

   Symptom: `modifications.txt` reports 0 modifications even though opaque
   graphic content changed.

   Suggested assertion: changed opaque content must not be treated as equal.
   The first acceptable behavior can be conservative: mark the graphic as
   replaced or emit old/new opaque blocks without attempting internal word diff.

## Recommended Work Order

1. Keep release hygiene green: `cargo fmt --check`, `cargo clippy --all-targets
   -- -D warnings`, and `cargo test --all-targets`.
2. Add small automated probes for the definitely-wrong corpus cases above.
3. Fix wrapper/block ownership before broader visual rebaselining. This should
   address the duplicated wrapper family and repeated macro misses.
4. Fix figure caption and footnote edit surfaces.
5. Strengthen contextual page-region handling for `41-43`.
6. Define the opaque content policy, then fix package/graphic cases without
   silently treating changed opaque blocks as unchanged.
7. Only after the code-owned failures are fixed, review remaining corpus
   failures for intentional reference updates.

## Design Risks To Keep In View

- `plain_text()` is still used in places where it can accidentally become an
  identity signal rather than a similarity/logging signal.
- Empty-text realized blocks are dangerous owners. Wrapper bugs are tied to
  opaque or empty realized blocks and unrelated tag/layout artifacts.
- Unique-descendant and duplicate-text-signature logic are bridge mechanisms;
  long term, edit ownership should come from annotated paths or block ownership.
- Rendered page-region diffing is currently a second pipeline based on laid-out
  text extraction and generated Typst snippets. It needs stronger provenance and
  less source-string recognition.
- Opaque content must have an explicit replacement policy. "No text" should not
  mean "no change."
